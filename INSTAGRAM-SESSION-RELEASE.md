Instagram WebView session checks now also verify the current user through a same-origin, read-only request using the browser-owned cookies. Signed-in page evidence is accepted, with a current-user server check when that evidence is unavailable; cookie presence alone is never authentication proof. Expired-session and checkpoint responses remain blocking. Checks reuse one request per document, and the Check button explicitly retries. An inconclusive check now shows a useful status instead of indefinitely saying checking session.

HD viewing no longer rejects Persistent WebView Session solely because the saved Verified preference is missing. The shared broker still authenticates and enforces security holds. Instagram Service Worker requests use the existing allowed-origin policy instead of a global network block. Manual cookies and existing signing identity remain unchanged.

Offline tests cover HttpOnly cookie use, accepted and mismatched user IDs, cookie-only/anonymous responses, expiration, checkpoints, one-request reuse, and HD authentication without cached verification. No live Instagram account has been tested; successful real-account authentication or HD display is not claimed.
