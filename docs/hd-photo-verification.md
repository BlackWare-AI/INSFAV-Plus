# HD viewing: avoiding repeated image downloads and thumbnail encoding

Prepared for a future APK; no version, workflow, package, signing, cookie controls, or interface changes.

Every HD open still resolves current identity-bound profile metadata through the existing provider. A cached image cannot bypass a login, challenge, default-avatar or profile identity failure. For recognized numeric Instagram CDN media-object filenames, the current media path and all content/transform query parameters must match. Only a fixed list of signing/routing query parameters is ignored; a change to an unknown/content parameter or transform prevents reuse. This relies on the CDN's immutable media-object IDs. It does not treat an arbitrary unchanged URL as proof of unchanged image content.

The private HD cache verifies SHA-256 before reuse and retains at most 64 images / 64 MiB. Cache hits avoid both the native image request and the Legacy probe's eager Image() request for a matching, freshly identity-bound JSON candidate. Conflicting header candidates, missing/invalid cache entries and new IDs use the original resolver/download path. Unknown/mutable URLs require a strong ETag conditional GET; 304 reuses the validated local bytes without reading a body. Changed/unsupported validators fetch the current body. No stale-cache fallback is used on authentication/security failures. Cache loss/eviction requires another HD download; old 256px thumbnails cannot reconstruct HD detail.

Before queuing a 256px conversion, a separate private receipt must match both the downloaded HD SHA-256 and the actual valid thumbnail SHA-256 in the selected folder. A matching pair skips encoding, spinner/job creation and writing. Missing/changed files or new HD content use the existing verified writer. Even when an already existing WebP is identical to the generated result, its verification receipt is established without rewriting that file. Existing image JSON/SQLite formats and the safe final byte comparison are retained. The receipt is checked again in the worker, including recovered jobs. Filesystem document IDs permit direct validation of the selected file without enumerating the folder; opaque document IDs use the existing folder lookup. An existing thumbnail without a receipt needs one conversion comparison to establish the baseline.

Tests cover signature rotation, changed media/transform/user, corrupt HD cache, strong ETag 304 without a body, a changed mutable response, absent validators, repeated conversion skipping, missing/changed thumbnail repair, receipt seeding, fresh profile checks and security stops. Browser tests prove the cached candidate avoids duplicate HD loading and preserves changed-photo/login-wall behavior. Responses are controlled; no live Instagram success is claimed.
